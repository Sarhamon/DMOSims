범용 유저간 거래 중개 봇 기획 문서

메이플스토리 라운지 형태의 유저간 거래·커뮤니티 기능을 공식 API가 없는 게임에서도 운영할 수 있도록, 디스코드 봇 기반으로 설계한 기획 정리본.

1차 적용 대상디지몬마스터즈 (DMO)
수익 모델완전 무료 커뮤니티
거래 방식매칭·중개 전용 (에스크로 없음)
01

인증

서버 참여 자체보다, 매크로·부계정을 걸러내는 진입 장벽을 우선한다.

디스코드 인증

서버 인증 레벨을 최고 단계로 설정해 휴대폰 인증이 완료된 계정만 채팅 권한을 얻도록 한다.

가입 승인 큐

신청 시 계정 생성일·가입 패턴 등 리스크 신호를 자동 수집해 관리자 채널에 게시하고, 매크로 의심 시 관리자가 직접 승인/거절한다.

02

거래 등록 흐름

유저가 직접 글을 쓰지 않고, 봇이 모달 입력을 받아 정형화된 형태로 게시한다.

01

등록 요청

유저가 명령어 실행 → 봇이 모달(아이템명·가격·설명) 표시. 10분당 1회로 제한.

02

리스팅 게시

모달 제출 시 봇이 거래 채널에 임베드 + [구매하기] 버튼으로 게시.

03

매칭

구매자가 버튼 클릭 → 비공개 스레드(티켓) 개설, 판매자·구매자·봇 초대.

04

거래 완료

[거래완료] 버튼 클릭 시 리스팅 상태 변경, 완료 거래 건수 반영. 원본 메시지는 삭제 대신 "판매완료" 표시.

03

신뢰 신호

별점·평가형 평판 시스템은 조작에 취약하고 관리 부담이 커 채택하지 않는다. 대신 조작이 어려운 최소 신호만 노출한다.

인증 경과일

예: "인증 127일차" — 가입일 기반이라 조작 불가능.

완료 거래 건수

평가 없이 숫자만 카운트. 예: "완료 거래 12건".

04

사기 신고 · 제재

에스크로가 없는 구조에서는 신고·제재 절차가 사실상 유일한 안전장치다.

신고

접수 시점

거래 진행 중 상시 가능 + 거래 완료 후 일정 기간 내 추가 접수 가능.

처리

에스컬레이션

관리자 전용 채널로 자동 전달 + 해당 거래 스레드 즉시 잠금(증거 보존).

기준

정당 신고 3회

관리자가 근거를 확인해 "유효 신고"로 인정한 건수만 카운트 — 단순 신고 접수 횟수가 아님(허위 신고 어뷰징 방지).

결과

제재 수위

정당 신고 3회 누적 → 서버 추방. 사기 확정 → 영구밴 + 블랙리스트 등재.

05

이의제기

제재 대상자의 이의제기와, 원 신고자의 소명 요청을 분리해서 둔다.

항목규정
신청 주체제재 당사자
가능 기간제재 후 3개월 이내
횟수1회 (신청~심사완료를 하나의 건으로 취급, 자료 보완 왕복은 소진 안 됨)
심사자원 제재 결정자가 아닌 다른 관리자가 교차검증
인용 시공개 블랙리스트에서만 삭제 (내부 그레이리스트는 유지) + 원 신고자에게 소명 요청 창구 오픈
기각 시블랙리스트 유지, 재이의제기 영구 불가
소명 요청 창구는 판정을 다시 뒤집는 절차가 아니라, 원 신고자에게 번복 사유를 설명하는 데 한정한다.
06

그레이리스트 · 블랙리스트

공개 페이지와 내부 기록을 분리해, 오판 정정과 이력 보존을 동시에 만족시킨다.

내부 전용

그레이리스트

  • 관리자만 열람 가능
  • 삭제되지 않고 영구 보존
  • 신고 원본·증거·심사 과정·이의제기 이력 전체 기록
  • 재범 추적, 소명 요청 대응의 근거 자료로 사용
외부 공개

블랙리스트

  • 전체 유저 열람 가능
  • 이의제기 인용 시 즉시 삭제
  • 현재 유효한 제재 대상자만 노출
  • 디스코드 ID + 증거 기반 기재, 실명·닉네임 낙인 최소화
07

인게임 비매너 트랙

거래 사기와 성격이 달라 별도 트랙으로 분리한다. 서버 추방 없이 거래 등록 권한만 제한한다.

누적제한 기간
1차3일
2차7일
3차14일
4차30일
5차영구 (이의제기로만 해제)

증거 기준 영상 또는 복수 목격자 필수

게임 내 스크린샷은 조작 가능성이 높아 단독 증거로 인정하지 않는다. 확정 시 can_trade = false 플래그만 부여하며, 채팅·서버 이용 등 다른 권한은 그대로 유지한다.

이의제기 규정은 사기 트랙과 동일하게 3개월 이내 / 1회 / 교차검증을 우선 적용. 처벌 수위가 가벼운 만큼 추후 간소화 여지 있음(미정 사항 참고).
08

기술 스택 메모

배포 계획은 없지만, 실제 착수 시 참고용으로 검토했던 방향.

서버리스 (Cloudflare Workers + D1)

디스코드 HTTP Interactions Endpoint 방식으로 상시 서버 없이 운영 가능. 커맨드·모달·버튼 상호작용은 전부 커버되나, 실시간 게이트웨이 이벤트(입장 감지 등)는 별도 검토 필요.

09

미정 사항

다음 논의에서 이어갈 항목.

  • ·
    비매너 트랙 이의제기 간소화 여부 open현재는 사기 트랙과 동일한 규정을 적용 중. 처벌 수위 차이를 감안해 담당자 단독 재검토로 완화할지 검토 필요.
  • ·
    DMO 외 게임으로의 확장 로드맵 open범용 설계이나 실제 확장 시 게임별 채널/카테고리 구조를 어떻게 나눌지 미정.
  • ·
    소명 요청 창구 세부 UX open버튼/티켓 형태, 응답 기한 등 구체적인 흐름은 아직 설계 전.
아이디어 구상 단계 기록 — 실제 개발 착수 전 언제든 갱신될 수 있는 문서입니다.
